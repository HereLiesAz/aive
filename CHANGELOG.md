# Changelog

All notable changes to **The Aive** are documented here from the current product line forward. Every merge to `main` ships a `MAJOR.MINOR.PATCH.BUILD` build (the line is `app.versionName` in `gradle.properties`; see docs/VERSIONING.md); builds of one patch line are grouped under one GitHub Release. The `0.9.6` heading below is where this log starts, not the current line.

## 0.9.6 — from 2026-09-19

- **Templates: the 26 steps without a starting template have one.** Nine new presets (`change-code`, `render-image`, `render-video`, `compose-media`, `edit-audio`, `make-slides`, `localize-content`, `fixed-format-result`, `capped-text-result`) are made from the existing step templates by changing data only; the ones that change something ask first and try once. The built-in swarms' and 8 packages' steps that were listed as gaps now name them as starting points (nothing about how those steps run changes), the gap list is empty, and a test fails if any of the 26 loses its template.
- **The queen can suggest a specialist, Android takes an owner token, and a setup file's pairing is reported honestly.** (1) When a generic role (no specialist yet) has finished at least five steps over at least three runs in one project, she offers **Train a specialist** in Messages, with a link to the Roster where the role's entry starts the training; counted from earlier runs with no model, withdrawn once the count no longer holds, never started or adopted without you (adoption still needs your approval). A project stands in for the domain. (2) Android's relay row under Settings now has an **Owner token** field (kept in its own Keystore-encrypted file, excluded from backup), used to re-enrol this device after a revoke and to revoke another; the desktop still reads `AIVE_RELAY_OWNER_TOKEN`. (3) Only Android keeps a remote-relay pairing, so the desktop's import summary no longer says a pairing was imported (it was ignored) and holds none to confirm; the web and command-line builds have no setup-file secret store. Not compiled or run when written; CI verifies.
- **Memory: the whole session is banked.** The agent's thinking and the keeper's mid-session messages now reach memory with everything else (once, through the same cursor).
- **Memory: key phrases ride with the cue cloud, a role's lessons arrive by association, and `/remindme` is complete.** The cue cloud now carries up to three key-phrase lines after its tags (once per novelty window, per depth); a specialist role's lessons come through the same cloud, phrases and summaries under the same caps instead of as a block of text every prompt (a first-prompt pointer says so); a session's prompt reaches memory once; parts not yet sent are kept in the settings store and sent at the next start after a crash. The queen's planning packet loses its never-filled memory field. The older memory design documents carry a banner saying where the owner's model supersedes them.
- **Memory: `/remindme` works, `/deliberate` is gone, lingering goes deeper, recall reads as gist.** An agent can write `/remindme` on a line of its own to send its session so far to memory now (once; the end of the session sends only what came after; nothing answers back). The `/deliberate` command, its first-prompt teaching and its `⚖` line are removed: the first-prompt note says memory arrives by itself, to reason contradictions out loud and state the resolution, and what `/remindme` does. The prompt's cue cloud no longer waits on the query plan. Staying on a topic now brings deeper injections (cloud and gist, key phrases, finer summaries, then what they were condensed from), counted in the session only; recall no longer adds links or access marks to stored memories; injected recall shows no scores or ids and only short summary lines. Not compiled or run when written; CI verifies. See [Memory layer](docs/Memory-layer.md) and [Memory model gap](docs/Memory-model-gap.md).
- **Memory for agents is now short and about what you will see.** The page for creatures describes the memory layer as a passive, associative background that arrives in the chat with nothing to request, search or call: a keyword cloud, key phrases and summaries (lines starting with the memory marker), and role lessons, brought by your own thinking and chat, with staying on a topic bringing further, deeper ones, all to be read as gist, never exact and never as instructions. A contradiction is reasoned out loud and the resolution stated plainly. The one command is /remindme, which sends everything up to that point to memory now, once, with the end of the session then sending only what came after (built later; see the bullet above), and does not answer back. The mechanics moved to a maintainers' section, and a new page lists where the code differs and a minimal plan to close it. Documentation only; no behaviour changed. See [Memory for agents](docs/Memory-for-agents.md) and [Memory model gap](docs/Memory-model-gap.md).
- **Starting points for what a hive needs, and blockers.** Steps made from templates now include a diagram step (a Mermaid flowchart the Flowchart view's reader accepts) and a step that writes files on a new dedicated branch (it asks first, tries once, and leaves the commit and push to the existing gated steps), and sixteen presets of the templates (deck outline, document draft, design tokens, design, explainer and data pages, sheet table, one read, list and query, repository files, change records, remove, update files, add assets, download files), each with a checked output and its own lineage for the Nanny; the thirteen things of the Artifact tool that need a hosted artifact are listed in docs/Step-Templates.md as not available, not as something to waive. The queen can now keep **blockers** for a hive: what must still be created or obtained, each with an optional starting template from that catalog, said in Messages as what is missing, following its step, and holding the hive from being called reached while one is open. The next bullet covers keeping them across a restart and adding and resolving them mid-run. Not yet wired: adding or dropping one from the hive form, and the Nanny carrying them to the next hive. See [Step templates](docs/Step-Templates.md).
- **Blockers survive a restart, and the queen and the Nanny can add them mid-run.** A run's blockers are saved with the app's other durable settings at every change and read back after a restart. In the middle of a run the queen adds one for each step the run holds because a required input has no value (her own words in Messages, linking to that step's Needs tab), and a Nanny finding whose subject starts with `missing:` becomes one too (its observation is the sentence, quoted); each is added once, even after the keeper drops it. A blocker with no step of its own is marked made when the step waiting on it is no longer held, or when a finished step made from its starting template has handed back output, and Messages says so in plain words. Each blocker is a row of the queen's in Messages with its link to where it can be changed; no new screen. Not done: dropping or marking one from the keeper's side, and the carry-forward to the next hive.
- **Every package and built-in swarm starts from a template, or says why not.** The coding suite, the short film, the starter swarm and the 64 workflow packages that make something now name the starting template of each producing step (write a document, check the work, or turn text into a table), with its typed output; the step runs exactly as before, because the contract only records where it started and the Nanny can improve that template over generations. Every role has a role template. 26 steps that fit none (code changes, images and video, audio, slides, localizing, fixed-format results) are listed as gaps in docs/Azphalt-Templates.md, and a test fails when a new package or swarm ships a step with neither. Changed packages have their version raised by one patch and their digests recomputed.
- **The queen's reviewer asks another Source and is skipped, with a reason, when a price, cap or limit says so; she knows when the hive is reached; and one place decides when she needs you.** An unpinned reviewer asks a Source other than the planner's first (a pinned one never switches). When the reviewer's model has no known price under a dollar cap, half the hourly cap is used, or its Source has no room, it is not asked: the checklist code can tick is the whole review, and Messages says why with a link to **Change the caps** or **Connect a Source**. What planning did (who planned and reviewed, on which Source, rounds, how many rules were met) is one Story line, and the reviewer's ideas beyond your requirements are kept in the improvement ledger for the next run, never applied to this one. Her own calls now read the real price from the price table, the real hourly spend and whether a creature is waiting for room. The planner may name what shows the hive is reached (`hiveSigns`); a swarm that finishes without them is said to be finished but not reached, with where to look. `needsKeeper` is the one place that decides what is yours to decide, asked by her priced calls, adoptions, suggestions, disputes and rulings. Engine: a swarm that has the plan-approval step can take the queen's staffed steps in the same run, only behind your approval and the validation any plan meets (nothing calls it yet).
- **Steps with a contract, and templates that improve.** Add creature offers six steps (write a document, make a page, turn text into a table, check the work, read from a connected tool, change something in a connected tool) run by a new generic Worker, the Reviewer or the Researcher. Each declares its inputs, the one tool it may use, a checked output and what it may change; a step that changes something always asks you first and tries once. The Nanny can propose a quick change or a new generation of a step or of a role through Improvement, with its aim and evidence, adopt and Revert keep a lineage, and locked fields never change by proposal. See [Step templates](docs/Step-Templates.md).
- **A training swarm turns a generic role plus a domain into a specialist.** An ordinary swarm of generic creatures (Planner, Researcher, Trainer, Reviewer, Nanny, Antagonist, the queen): scope, research through the keeper-approved path, sourced lessons, practice of the generic role against the draft on tasks generated each run, a Reviewer's scores, the Nanny's pass, refine or stop (a cited listed fact, else the fixed rules, else you), one Antagonist challenge, and a Messages offer with the practice results. The Trainer may only tighten limits. Nothing is adopted without your approval; the variant keeps the generic role as its parent and every lesson with its source and date. Memory banking of the lessons is a typed seam, not yet connected.
- **The queen checks plans against your requirements, notices a stalled swarm, and offers new wording or shape changes as suggestions.** A plan is checked by code against what you wrote or set (step limit, approvals in front of anything that changes the repository, available roles, plain names) and turned back without a model call when it fails; her model calls are gated on your spend caps and each Source's pacing. She notices a swarm that stood still for ten minutes and the same block in several steps. At Helpful she asks her model, once at half done and once after a second failure, for new wording for a step that has not started, offered only as a suggestion you accept. Repeated late failures can offer a check, a split, a new order or an approval to **Keep for next time**, never applied to the running swarm and never loosening an approval. She is in the Story and on a creature's sheet.

- **"Teach me how to use the Aive" starts a guided tour on the real screens.** Feeding a goal that asks to be taught the app also starts a hint layer over the real controls. About twenty controls (the launch form, the rail, the view switch, Pause and Stop, the creature tabs, the Keeper's room list) can now be pointed at.

- **A training round now runs itself, to an offer or a stop.** When a round's review is in, the Nanny rules, the Antagonist challenges once, the Nanny answers once and, if it is still unsettled, the queen settles it through the usual dispute route (both creatures must agree to her approach; her Source is your pin or Automatic, paced and held to your spend caps). A refine starts the next round with the findings; a stop or a non-pass cancels the offer, so you can never approve an adoption the ruling did not pass; a pass is offered in Messages and adopted only on your approval. - **The queen's disputes have a model, a fact-finder and a memory.** Her own calls (rulings, approach statements, a research's facts) use the Source of her creature: pinned (never switches silently) or automatic (your enabled Sources, keyless included, falling down the usual order); with none usable she is away. The Nanny and the Antagonist answer her approach through it with their own role text, every call held to your hourly spend cap. A research also returns up to three short facts that each cite their source, a finished test's report is read back for one more agreed ruling, and a raised dispute is not raised again after a restart.
- **The queen's calls wait their turn, and her moves between Sources are in the Story.** Her own model calls (and the Nanny's and the Antagonist's answers) now keep the same per-Source request limit the creatures' calls keep, so a dispute on a tightly limited keyless Source waits for its turn instead of failing partway. The wait is hers (never your waiting), bounded per call and per dispute; a turn that is too far off moves Automatic to the next Source and only then to you, and a pinned Source waits but never switches. When Automatic moves to another Source during a dispute, the Story of that swarm says which Source could not answer and which she asked next.
- **The Nanny hands findings to the queen, and what goes unused is carried to the next run.** A finding in the Nanny's report that reroutes one named step can reach the queen mid-run as a candidate for her suggestion menu (a link to that creature's Mind; she applies nothing, it is paced like her other suggestions, and you decide it with **Go ahead** or **No thanks**). The Nanny still works for the next hive or swarm: when a run ends, every finding the queen did not use is recorded once in the improvement ledger (source **from the Nanny**), which the next planning already reads as evidence. No model, no new screen. Nothing else of the Nanny's report reaches the queen as a suggestion yet.
- **The queen can look into a dispute.** When the Antagonist rejects the Nanny's report she raises it between the two creatures, and nothing starts until both agree to her one-line approach. If no listed fact settles it she may research (the existing research step and its consent question) or test the options in a small swarm of generic creatures under your spend caps, one investigation per dispute; if it cannot start, it comes to you in Messages. - **Accepting a queen suggestion is stricter.** It re-checks that the reason still holds (a redo only while the step is still failing, a rest only while the Nanny's review is pending), two overlapping taps run the change once, and the queen's 100 rows no longer push another source's proposals out of the ledger.
- **The queen suggests, mid-run, in Messages.** While a swarm runs she can offer one thing at a time (two at Helpful), as a Messages row with **Go ahead** and **No thanks**; each counts toward the Messages badge until you decide it. What she can offer is a closed menu, worked out from what she can count, with no model: redo a finished step and what follows it (when a step that builds on it has failed twice; it asks first), a link to a creature's Mind when a step moved to another Source or a role is at 80 percent of its token budget (a running swarm cannot change either, so it applies from the next run), a link to the allowance when the run has counted 70 percent of its cap with many steps still to do, and, while the Nanny's report is still being checked, a rest of the swarm (your own pause). She never offers to remove or loosen an approval, skip a step, or move work to a Source that can write to the repository. In a swarm that has a Nanny she does not judge whether the swarm is working: the Nanny's findings are relayed, never her own. Pacing: fifteen minutes between new ones, five a run, one per step and action, and one you dismissed is not offered again for the same step and action for two weeks, in any run; one that no longer stands (the step started, the problem passed) is withdrawn. Accepting applies only in the app, with the calls you already have, re-checks first, and marks it adopted only if the change took; a second tap changes nothing and says so. A suggestion built on content from outside (a web page, a remote launch) is labelled and a new job for a step is not offered from it. Suggestions are rows of the one improvement ledger (new source, **from the queen**), per run, capped at 100, and shown in Messages rather than the Keeper's room Improvement list. A reword of a step that has not started is built and tested (a live edit, refused for a step that can change a repository unless it sits behind an approval) but nothing writes the new wording yet: that waits for the model checkpoints. - **Security hardening.** Remote compute leases refuse GitHub Actions work, and only the relay owner can revoke another node or re-enrol a revoked one (set `AIVE_RELAY_OWNER_TOKEN` on the relay and the host). Artifact downloads from GitHub Actions follow the one expected redirect to a GitHub host without the token. A locked or unreadable system store no longer replaces this device's compute identity; without a system store, keys are kept for the session only unless `AIVE_ALLOW_PLAINTEXT_SECRETS=1` is set. The relay checks a session's pool before it exists, caps enrolment bodies while streaming and limits pools and leases. A remote pairing's relay is validated whenever it is read or imported, and a setup file cannot move an existing pairing. Remote model downloads accept `sha256-` and `sha256:` checksums, a failed reinstall keeps the working install, downloads are capped at their declared size and check free storage, and the downgrade guard covers model and language-model packages and orders pre-releases correctly. A hive card's import summary lists the objectives it supplies. A Nanny solution trial asks you to approve its generated plan first. Crash reports drop home paths and long number or hex runs. Exported trace content is scrubbed, a run is marked exported only after delivery, and the web build has a content security policy. The privacy page describes trace export.

- Memory is now organised per workflow run, like version history. Every run has its own memory bank. A run that continues another reads the earlier run's memory and adds to its own; a run that merges two lines of work reads both, and where the two lines remember different answers to the same question, both are kept and marked for the agent to weigh. A project is the set of runs about it and can be expanded to take in another project. A session recalls from its own run's history first, then, read-only and labelled, from the other runs of its project; nothing outside the project is visible, and nothing is ever written into another run's memory. - Consolidation now rewrites: condensing similar memories writes a new current version and the originals become history (kept, retrievable, out of ordinary recall). Memories that disagree are combined only after an agent has deliberated and named the one it judged correct; recall then returns that memory alone, with a note about the earlier disagreement that fades the more it is recalled, and new contradicting evidence reopens it. A memory never grows: each rewrite fits a size budget that shrinks along an S-curve to a recognisable gist, keeping the most salient sentences, and detail that does not fit becomes its own linked memory. - Memory now tells "similar" from "same question, different answer".

# Changelog

All notable changes to **The Aive** are documented here from the current product line forward. Every merge to `main` ships a `MAJOR.MINOR.PATCH.BUILD` build (the line is `app.versionName` in `gradle.properties`; see docs/VERSIONING.md); builds of one patch line are grouped under one GitHub Release. The `0.9.6` heading below is where this log starts, not the current line.

## 0.9.6 — from 2026-09-19

- **The queen speaks in Messages, and the Nanny's reports reach you.** Messages is one list and one page on every width: the Nanny's freeze, a spend stop and a practice run are rows of it, the Nanny's review and solution test have their own callbacks, and a finding's scope and a solution's action read in plain words. The queen adds sentences to the rows that exist (what Retry will do, a spent budget, a spend stop in her words) and relays the Nanny: a report being checked, a report the reviewer sent back or rejected (never shown before), and, while frozen, what froze, the top finding, her own read and any practice run. Text from the run is quoted on a separate labeled line, never put into her sentence. A swarm with no Nanny gets her own "I noticed" for a step that failed twice, moved to another Source or is near its token budget, and a finished swarm gets one note. Her notes are derived, not stored, and never count toward the badge. **Keeper's room › This device** (Limits when wide) has one chooser, Quiet (default) or Helpful (adds a living status line); no level calls a model. Suggestions and model-worded checkpoints are not built yet. See docs/Keepers-Room.md.
- **One route to Connections and the orphan row says what it knows (cluster A).** The two copies of "open Connections" (one in the ControlRoom, one in its main destination) are one function, `openConnectionsPlace`, that can also open **Connect remote agent** with an address filled in. Every mention of a source is now a link to where it is changed: a hive card's "runs on" and "needs" lines and its orphan line (which opens the connect form with that address), the Work tab's Source and Source target lines (the source's own screen), a Delegations row's source, and a Memory clerk's unconnected source. The directory section is headed **Orphans**, its button is **Look for orphans**, and each result row carries **UNVERIFIED** and **LIVES ELSEWHERE** badges (not the second for an address on this computer), **Good at:**, **Source: not stated** (or **Source: X (declared)** when SearchA2A supplies it) and **Host: <hostname>** (no vendor is guessed from a name), a registry note only when there is one, and the one sentence that says why none of it is proven. Examples to try wear the same badges. The per-gateway **Try it free, no key** card in Connections is gone: the **Keyless sources** switch above it does the same in one tap. Nothing new on screen: rows, links and lines only. See docs/architecture/AGENT_DIRECTORY.md.
- **The creature sheet is the care surface, and links to where things change (cluster B).** Mind, the Source row and the job on Work no longer edit in place: each links to its one editor (the Roster role form, which now also holds the kept creature and the proposed instruction changes; the swarm's Edit view; Compute; Delegations). Nothing new on screen. See docs/Keepers-Room.md.\n- **Back returns to the creature you left (cluster C).** Leaving a creature's panel for Connections, Compute or Limits and pressing Back lands on that creature and the tab it was on, not the bare hive. Every way to go to a place is one `navigate` helper in `App.kt`; the history is a pure function (`NavigationHistory.kt`). Creature meters on Needs read **HP** and **MOOD**.\n- **The first segment of the view switch says what the run is (cluster V).** There is no Live unless a run is live: the segment reads **Live** while a run is unfinished (paused or waiting on you included), **Rehearsal** while a rehearsal plays, **Success** when the run ended completed, **Failed** when it failed or was stopped, and is absent for a hive that never ran, which then shows only the other views. Tapping it shows the same run view as before, a finished run in its final state. `runSegmentLabel` is a pure function (`RunSegment.kt`).\n- **Text fields fill themselves in.** The first launch starts the goal with the last one you fed, or a starting goal for the linked repository (a fixed template, no model is asked), and the repository with the last one you used for that kind of source, recent ones first in the search menu. The launch bar, the feed bar (a finished swarm starts with its own goal, selected, to run again with a tweak), a continuation (starts from the run it reads), the swarm prompt, the hive name (starts with the name the planner drafted) and a role's standing instructions (also one choice that adds waiting lessons to the draft) offer what you typed there before. A step that failed, escalated or is blocked starts its message to the agent with "Retry with: <why it stopped>", scrubbed and cut to 160 characters, and a rerun offers the same line. Typing replaces a suggestion, and a suggestion you did not edit is never saved as a draft. Up to 12 recent entries per kind stay on this device, are never sent or exported, and a key-like text is never kept; **Keeper's room › About and privacy** has one switch (on by default; off deletes them) and **Clear remembered text**. Key, token, pairing-code, header, passphrase, memory import/export and script fields are never filled in. Not done: Connections endpoint history, and the Android backup still includes the remembered text (see docs/PRIVACY.md).
- **Keyless sources start on.** The free sources that need no key (Kilo Gateway, LLM7, OVHcloud AI Endpoints, and the AI Horde image generator) are now connected the first time the app starts, with no tap, once each: a source you disconnect afterwards stays off, and a keyless source a later release adds is turned on once. A fresh install can feed a hive straight away. **Connections** has one **Keyless sources** switch that turns all of them off (or back on) and one line saying that prompts and repository text sent to a keyless source leave the device and may be logged; the first-run form carries the same line. Automatic choice puts a keyless source behind every source you added, keeps it inside the limits the catalog states (Kilo 200 requests an hour, OVHcloud 2 a minute), and never gives it a creature set to another source. Remote agents, store models, command-line agents and Ollama Cloud (an account key, and credits for its larger models from 2026-11-09) are never turned on this way. Spend caps, approval gates and taint rules are unchanged: a keyless source still reports no cost because it cannot bill, and its output is as untrusted as any provider's. A source you had disconnected before this release cannot be told from one you never touched, so it is turned on once at the first launch of this release. See docs/Keepers-Room.md and docs/PRIVACY.md.
- **Saving a project on Android replaces the file atomically (P15).** The save deleted the old project file before renaming the new one into place, leaving a moment (and, on a crash, a lasting state) with no project file. It now moves the new file over the old in one atomic step.
- **A picked folder's entry names are checked before import (P16, Android).** Importing a folder through the Android document picker joined each provider-supplied display name onto the copy's path, so a name like `../x` wrote outside it. A name must now be a plain file name.
- **Cancelled text-provider sessions and the CLI no-hooks folder no longer pile up (V25).** A text provider kept a cancelled session in memory when nothing was watching it (or the watcher was stopped from outside); it now drops it. Each command-line-agent provider made its own empty `aive-cli-nohooks-*` temp directory and never removed it, and providers are rebuilt whenever settings change; they now share one per temp folder, removed when the app exits.
- **Cloudflare account ids are checked; remote A2A tasks are polled less often (V24).** The Cloudflare Workers AI account id, spliced into the request URL, is now limited to letters, digits, dashes and underscores (a slash, dots or a query could have sent the key elsewhere on the host). A remote A2A task is still polled every two seconds for its first polls, then at growing intervals up to 30 seconds while nothing changes, backs off after a failed poll, and is reported as not finished after two hours (it was six).
- **Remote replies are read with byte caps (V23).** Model, repository, package-store, compute-relay and duplex-peer replies were read whole with no size limit, and the duplex notification stream read lines without one. A success is now read up to 16 MiB (past that the call fails), a failed reply is only quoted (16 KiB read), and the duplex stream refuses any line over 1 MiB without capping a stream that lives long.
- **The tool loop has a token budget and no longer re-asks after a billed failure (V22).** The MCP tool loop capped rounds but not tokens (each round replays the whole exchange), and any failure of its first request, including a timeout or a 5xx that may have been billed, made the provider generate the answer again without tools. The loop now refuses tools for its last turn once 400,000 tokens are spent, and only a 400, 404 or 422 (the model not taking tools) falls back to a plain generation. Its JSON replies are read with a byte cap.
- **Claude's thinking-mode fallback is atomic (V21).** Two streams refused at once for the same thinking mode each stepped the shared mode forward, skipping the fixed-budget mode straight to none. The step is now taken once under a lock.
- **The inference state is bounded (V15).** The one stored value behind the compound-inference fabric (stream records, resource samples, run bindings, invocation sequences, data descriptors) only grew and was rewritten whole on every event. Each list now keeps its newest entries (2,000 records, 500 samples, 1,000 bindings, 2,000 sequences, 5,000 data descriptors); the value was already stored in chunks.
- **Hosted text APIs share one HTTP client (V14).** Every hosted text API (and the memory clerks, which build one per call) created its own HTTP client and never closed it, leaking a connection pool and threads each time. They now share one process-wide client.
- **A paid generation is not run twice by the observer's retry (V13).** For a text provider the generation runs inside the observer's flow, so when the observer faulted (or ended without a result) the gateway collected it again after a backoff, which ran, and billed, the generation again. A provider now says `observeDrivesBilledWork`; the gateway fails such a session at the first fault instead of retrying it. Providers that only watch remote work keep their retries.
- **Errors are classified by status and code before words (V12).** A failure message was sorted by the first matching word, so a 400 about a `billing_address` field read as "Out of credit" and a 500 from a "quota service" as a rate limit. The status and the provider's error code (402, 401/403, 429, 5xx, 400, `insufficient_quota`) now decide first; the loose words (billing, quota, authentication, overloaded) are the last resort when there is no status.
- **Streamed model output has a cap (V10).** The OpenAI, Claude, Gemini and compatible-endpoint streams grew their answer without limit, and read their lines unbounded. A stream now stops with a "truncated" error at two million characters of answer and reasoning (about half a million tokens), reads its lines through the bounded reader (64 MiB on the wire) and quotes at most 16 KiB of an error body.
- **A failing memory clerk backs off and honours Retry-After (V9).** When the model behind a memory clerk failed (a 429, an outage), the memory drain asked again at once for every attempt. It now waits after each failure, doubling from one second up to a minute, and never less than the provider's `Retry-After` (capped at five minutes), which the hosted APIs now carry on their errors.
- **The runtime no longer works on the UI thread (V4).** The runtime's cycle (polling sessions, persisting runs) ran on the UI's coroutine context and every workflow-database call was a synchronous SQLite call on that thread. The app now starts the runtime on `Dispatchers.Default`, and the Android and desktop workflow databases run their SQLite calls on `Dispatchers.IO`. Both dispatchers are injected (null keeps the caller's), so tests stay deterministic.
- **Node-creature pictures are kept as files (V5, desktop).** The source character and rig sheet (megabytes of base64) were stored in the artifact's `uri`, copied into every saved run each cycle and printed as text in the Inbox. On the desktop they are now written to `~/.aive/node-creatures/images/` and the artifact keeps the file reference. Android and the web build keep the data URI (no store is wired there yet).
- **The node-creature image pipeline has a budget and reports its spend (V3).** One dispatch made up to 12 paid image and vision calls, was retried by the workflow on failure (each retry paying again), and reported no cost. It now stops at a call budget (12, `maxCallsPerDispatch`), is no longer retried by the workflow, and reports the tokens it used and their price on success and on failure. A call that failed without an answer is counted, and the image model is not on the price list, so the cost is reported as unknown rather than free and a dollar cap stops the run.
- **A memory interrupt is counted as spend (V7).** When memory interrupted a streamed generation and it started again (up to three times), the abandoned stream was billed but reported no usage. Each abandoned attempt is now added to the run's usage as an estimate (three characters a token, deliberately high), so token budgets and dollar caps see it.
- **Five words renamed on every screen.** Timeline is now **Story**, Provider is **Source**, Inbox is **Messages**, Hall Monitor is **Nanny** and Drifter is **Orphan**; Memory and Breed stay. The words change in the app's text, labels for screen readers, notices and the docs that name screens ([Vocabulary](docs/Vocabulary.md) maps each to the code's own term). Nothing underneath moves: code names, saved keys, the hive card, the A2A Agent Card fields and the Remote API are unchanged, and a Nanny trial saved before this change is still recognised. A test keeps the old words out of the string resources.
- **OpenCode workflow keeps the repository token away from the install step.** The `aive-opencode-agent.yml` The Aive installs now sets the write token and the task only on the step that runs OpenCode; the `npm install` of OpenCode no longer sees them. Repositories that already have the file get it updated through the usual approved-plan install.
- **First-timer UX fixes (cluster UX1).** A failed Approve, Reject, Stop, Pause, Lift or Retry now shows a dismissible notice (what failed, one plain sentence, the raw text behind **Technical details**) instead of flipping the whole app to STOPPED. Raw provider text is said plainly in Swarm Activity rows, the wide status line, the Flowchart card, the launch error and the Inbox escalation (no internal code), with a provider's 400 told apart as "did not accept this request". The header and rail Inbox open the Inbox, which lists all six kinds of wait the badge counts (on a phone too); every row leads to where it is resolved (**Answer it**, **Raise its budget**). A creature's Needs shows the plan, with **Show full plan**, above Approve and Reject. Approval is an On/Off switch (turning a person's approval off asks first), Retries a 1-5 choice, Runs on two choices. The web build hides the Compute part. The first-run free providers are text writers, best limits first, with a plain line about where prompts go. Compute Disconnect, New token, Forget, Replace memory, schedule Remove and Discard the unreadable list ask first. User text names places as they are now called (the Keeper's room, the Hive, the Roster; the spend caps under Limits on a wide window). Hard-coded English in the credential screen and the memory layer moved to string resources; the unreferenced `CompanyProviderScreen` is deleted.
- **Flowchart cards say what is happening and where to fix it.** Tapping a card in the Flowchart opens a panel with one plain sentence (what the step is doing, or what holds it: an approval, a question, a spent budget or spend cap, no reachable device, an unavailable integration or provider, a failure, a step it waits on) and one button to where that is unblocked (Open inbox, Raise its budget, Open spend limits, Open Compute, Fix in Connections, Show the step it waits on, Open creature). On a phone a creature's bottom sheet now opens only in Live and Build; in Flowchart the card's panel answers the tap. See docs/Keepers-Room.md.
- **UI state, accessibility and phone-layout fixes.** Opening the Inbox badge now leaves a resting hive; a remembered resting hive that was wiped, imported over or recovered away is forgotten (after a successful load only) instead of stranding the shell; deselecting a creature forgets its remembered tab; the Workflows editor no longer inherits the Overview's tap-to-release; deleting a creature from the swarm deselects it even if its panel was set aside; a queued "feed it more" objective is kept until its launch has started a new run (it was dropped before the launch, so a refused or failed launch lost it); a creature's saved job survives a live edit of the hive; the Log follows a creature reassigned to another role; Rewind and turning a schedule on ignore a second tap while the first runs. Screen readers: a clickable record is one button whose label includes its body and a non-clickable one is no longer merged; a record's well (Approve, Reject, fields) is reachable; the Inbox detail's buttons are outside its live region; the status line and task-activity rows are no longer live regions that announce every thought; flowchart boxes report selection and the flowchart draws on Ink (its arrows and labels were black on Ink); link rows are at least 48dp, carry a cue (a chevron, or an underline) and the hive-menu has a long-click action for assistive tech. Secondary text is at least 4.5:1 (it was 3:1). Reduce motion now also stops entrance slides, the selection growth and child-band growth. The Timeline's Events tab is a lazy list sorted once, a failing timeline loader says so, the 28sp objective is capped at four lines, a phone gets the shorter field, the wide controls bar puts its status on its own line below 560dp instead of clipping, and the repository suggestions no longer take focus from the field while typing. The Hall Monitor review buttons and several remaining English strings moved to string resources; dead sample-data screens (CompanyScreen, WorkflowTemplateScreen, the non-live Inbox list) were removed; docs/Keepers-Room.md no longer says two different things about what a creature "needs".
- **Independent The Aive headless orchestration engine.** The `aive` JVM CLI now boots `ApplicationRuntime` and its workflow coordinator without the desktop UI. `run` and `resume` work in the foreground, `serve` provides an authenticated local daemon, a separate SQLite store and an exclusive lock prevent duplicate dispatch, and owner decisions remain in the attached keeper terminal. Hosted LLMs and supported GitHub/GitLab executors use environment credentials. See docs/CLI.md.

- **Self-improvement ledger remembers every cycle it has read.** The ledger kept only the newest 200 cycle records, and startup backfill treated an older cycle as unread, re-importing its proposals as Proposed (resurrecting dismissed ones, duplicating adopted ones). It now keeps a separate, larger list of read run ids (5,000 newest) beside the bounded records. Cycles trimmed before this release cannot be recovered.
- **Loop integrity judges the role that really runs.** The self-improvement loop's independence checks (the examination is not the Hall Monitor's, or after it; the challenge is by a different role) read a step's declared role, not the role its executor dispatches as. They now use the executing role, as the dispatcher does.

The provider's description says so, and a refusal that says a model requires credits reads as "Out of credit ... Add credits" (it was missed or called a rate limit). The default model is still gpt-oss:120b: no model could be verified as still free, so pick another in Settings if you have no credits.

All Agent Card validation, explicit provider assignment, approvals, and trust restrictions remain unchanged.

Existing explicit-only A2A routing and approval gates are unchanged. See docs/architecture/AGENT_DIRECTORY.md.
- **Persistence, import and platform hardening.** A package id or version such as `..` is rejected when a package is verified (it could have deleted every installed model); a `.ive` file's roles never overwrite local or built-in roles (new ones arrive disabled); a setup file is checked setting by setting: it cannot move the compute relay without carrying its own token, replace a publisher pin, move an installed model's endpoint or register another device's model paths, and the summary lists what changed or was skipped; layout, inbox, ledger, dataset, memory-lineage and UI-draft stores no longer fail past the desktop 8192-character value limit and layout keys fit the 80-character key limit; an interrupted memory split no longer wipes later episodes; unreadable stored lists (MCP servers, improvement ledger, installed models, drifters, character assets, memory banks) are kept under `.corrupt` and never overwritten; importing a project writes before it drops event journals; recovering from corruption keeps the damaged text; packages installing a role grant it no authorities; installing an older version of a package needs explicit approval; drifters whose hosts differ only by punctuation get separate roles; the Android package activity opens only `content://` URIs; the installed-model record is left out of Android backup.
- **Memory layer hardening.** A condensed memory cut to its size limit is re-checked for the values and negation of its sources and declined if it lost them; Forget and raw retention no longer lose a session banked while they run; forgetting an episode also removes merged text that may restate it; banked sessions and role-instruction proposals are scrubbed of keys, and recalled memory is labelled untrusted data; a message starting with the memory marker is no longer left out of memory; the Memory screen offers to delete the pre-split memory backup; unreadable memory settings keep memory off instead of resetting retention; recall and habits read bounded amounts at each task start. The Hall Monitor pause now opens and its Orchestrator review runs by itself, with your review and resume on the pause screen. A habit decision is ignored if the task's own output was made from untrusted content. See docs/Memory-layer.md.
- **One clear route for remote agents.** Removed the duplicate hive-edge marketplace and the district's Bring in a drifter button. The Azphalt Store installs signed packages; Keeper's room › Connections now contains the optional independent A2A agent suggestions and the single Agent Card connection form. It validates card compatibility before adding a provider. No automatic role assignment or changes to stored agents, roles, and workflows.
- **Hive edge labels.** The two shelves now read **Drifters** and **Swarms**; the Agent Card entry button is **Adoption**. Actions and admission checks are unchanged, and **Bring in a drifter** on the district still opens the edge.
- **Store signature verification on Android.** Explicitly select bundled BouncyCastle to verify Ed25519-signed Azphalt packages instead of depending on Android's default JDK cryptography provider. A fixed signature vector from Azphalt guards against signing-format drift; manifest digests, signer identity and revocations are still enforced.
- **Plain-text breadcrumbs.** A hive's breadcrumb shows its linked GitHub, GitLab or local Git repository/folder before its name. Objective-generated hives use the project's name instead of the full launch prompt. The new-hive breadcrumb is text-only too.
- **One vertical Flowchart mode.** The workflow diagram now runs top to bottom, with arrows pointing downward. Live, Build and Flowchart sit together in the hive controls; the separate Creatures / Flowchart row and duplicate Timeline Flowchart tab are gone. Selecting Live or Build returns to the creature view.

- **A short-film hive (desktop).** Keeper's room › Schedules › **Add the short-film hive (desktop)** adds a hive that turns an objective into a short film made of still frames: a concept, a JSON storyboard, one style sheet, one image per shot from the image model (three at a time, two retries a shot), a frame review that can send single shots back, an `.mp4` that ffmpeg assembles from them (a `Media` artifact), and your approval. It needs the desktop app, an OpenAI connection and ffmpeg; on a phone or the web its two executor steps are blocked as not available. It spends money, so it is never scheduled and each run has an image budget (40 by default; `AIVE_FILM_IMAGE_BUDGET` raises it, and the step says so when it is too low). Frames are kept by what they are drawn from, so running the frames step again draws only the missing and the sent-back shots. Every limit is a named constant. The image API and the whole hive in the running app have not been tried live; the ffmpeg command was run against ffmpeg 6.1.1. See docs/Short-Film.md and the threat model's note on spend, ffmpeg paths and generated media.
- **The hive's long press, Pause, rewind, and more than two providers.** A long press on a hive's swarm opens a menu with **Delete hive** (it asks first, and refuses a running one). A closed creature sheet stays closed when you tap the ground; before, any tap brought it back. Every hive can be read as **Creatures** or as a **Flowchart**. A live run has **Pause** and **Resume** (nothing new starts, what runs finishes, nothing is cancelled); a saved edit to a creature that has not started reaches the live run; **Run again from here** on a live run stops it and continues from that creature. Auto work now takes turns over every provider that can do it, not only the first. A new hive's **Draft** first shows the closest of your saved hives, beside **See how the planner would do it**. The hive's activity rows and a creature's status line are now links to where they can be acted on.
- **LLM command-line tools as providers (desktop).** The app can drive the vendors' own CLIs headless (Claude Code, Codex, Gemini CLI, Qwen Code) under the login you already have, so no API key is needed for them. Keeper's room › Local agents shows which are installed, turns one on (off by default), and **Test** runs it read-only on a tiny prompt. A CLI runs only after you approved a plan, in its own git worktree on a new branch with a bare environment, and its edits are committed there for you to review; it is never picked automatically. The flags are written from the CLIs' documentation and are untested against every version: Test is how you find out. See docs/Local-CLI-Agents.md and the threat model's note on what a CLI can still do.
- **A self-improvement loop, and the Hall Monitor put to work.** The coding suite gains a **Self-improvement cycle**: the Hall Monitor reads the swarm's own run history (counts by role, hive and provider against the week before, and what earlier adoptions did to the numbers), an Antagonist challenges its report, an Architect and an adversarial reviewer examine **the loop itself**, and it ends in proposals. It only reads and proposes, so it can run weekly by itself. **Keeper's room › Improvement** lists the proposals with their exact text, how each would be measured and how to undo it; you approve and apply, dismiss, or revert. Everything that proposes an improvement now lives in this one list: the loop's own proposals, the role-instruction proposals drafted from run history (still on the creature's Mind tab too, and a decision on either is made on both), and the habits you can turn into a step (choose the hive to add it to). The loop reads the other two as evidence. A proposal about the loop is applied by the same code as any other, the loop must examine itself every cycle (or say, with evidence, that it needs no change), and the screen says when it has not. See docs/architecture/SELF_IMPROVEMENT.md.
- **Rewind in place, and more links.** **Rewind to here** on a creature restarts it and what follows as a new attempt while the rest of the swarm keeps running. Schedules take a UTC offset (Zone west / east). Agent log lines open their creature, a docked creature's card opens its job and provider, a failed launch offers **Check connections**, and a run stopped by a spend cap offers **Change the spend caps**.
- **A coding suite, and hives that run on a schedule.** Keeper's room › Schedules › **Add the coding suite** adds eighteen coding hives: feature delivery, bug fix, safe refactor, test coverage, dependency update, docs sync, release prep, incident hotfix (with a rollback branch when verification fails), a change review, a security audit, a codebase map, and six that run by themselves (nightly dependency audit, daily CI triage, weekly test health, security scan, docs drift and tech debt). Hives that change code are approved before they change it and end at your release approval; the scheduled ones only read and report. A schedule is off until you turn it on, runs only while the app is open, starts once for any number of missed slots, waits for the active run, and writes each decision in the App log. Times are UTC. See docs/Coding-Workflows.md and docs/Scheduled-Workflows.md.
- **The Log's tabs.** The Timeline's tabs and the Log's sources wrap onto more lines instead of scrolling off the edge, and the Log's sources are named Agent actions, Workflow log, Memory log and App log, with All activity first.
- **Habits, on the Memory screen (Technical view).** A **Habits: learning / off** switch lets the app keep short receipts of what system executors did (off by default; see docs/PRIVACY.md). With it on, an operation done three or more times is a habit: it is offered, as counts and facts and never as an instruction, to agents whose task names it, and listed on the Memory screen with how often it completed, failed or was turned back, the values it took, any flags, and any open contrast. You can add your own words to a habit: **Flag it**, **It stands**, **Replace it** (a new version begins) or **Override it** (what to do instead; three uses of a named alternative make it a habit of its own). None of it hides or blocks a habit, which can always be chosen. Operations that repeat in the same order across runs are listed as sequences. See docs/architecture/HABITS_AS_MEMORY.md.
- **What each role has done, across every run.** In the Roster, **Show activity** on a role lists its steps in every hive and run kept on this device, newest first, with how each ended, its attempt, and the tokens and cost its provider reported, above counts of steps, runs, completed, failed or escalated, tokens and cost.
- **Flowchart and activity by role on the hive's Timeline.** A **Flowchart** tab draws the workflow as boxes and arrows with each step's state (a step a condition skipped is dimmed, not red); tapping a box selects that creature. The Log gains **All activity**, the run's events and its agents' steps in one list by time, and every row now names its role; a row of role tabs shows only one role's steps.
- **A Refinement data panel on the Memory screen.** The switch that keeps finished refinement-ladder levels on this device (off by default) now has a screen: what has been kept, how many usable rows each level has of the 200 wanted before training is worth trying, the newest records as plain lines, copy as JSONL (the corpus builder's input), and clear.

- Memory is now organised per workflow run, like version history. Every run has its own memory bank. A run that continues another reads the earlier run's memory and adds to its own; a run that merges two lines of work reads both, and where the two lines remember different answers to the same question, both are kept and marked for the agent to weigh. A project is the set of runs about it and can be expanded to take in another project. A session recalls from its own run's history first, then, read-only and labelled, from the other runs of its project; nothing outside the project is visible, and nothing is ever written into another run's memory. - Consolidation now rewrites: condensing similar memories writes a new current version and the originals become history (kept, retrievable, out of ordinary recall). Memories that disagree are combined only after an agent has deliberated and named the one it judged correct; recall then returns that memory alone, with a note about the earlier disagreement that fades the more it is recalled, and new contradicting evidence reopens it. A memory never grows: each rewrite fits a size budget that shrinks along an S-curve to a recognisable gist, keeping the most salient sentences, and detail that does not fit becomes its own linked memory. - Memory now tells "similar" from "same question, different answer".
